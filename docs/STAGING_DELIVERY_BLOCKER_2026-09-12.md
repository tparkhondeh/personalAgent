# مانع باقی‌مانده تحویل به‌روز Staging

## گزارش کوتاه مالک

کد تازه روی محیط آزمایشی نصب و آزموده شده، اما MizbanCloud فایل به‌روزرسانی را چهار ساعت کش می‌کند. در مرورگر این میزبان نیز اتصال TLS بسته می‌شود و نسخه قدیمی ذخیره‌شده دیده می‌شود. این دو یافته مجزا هستند؛ اثبات نشده که علت قطع TLS، کش است.

اقدام ضروری: مالک پنل MizbanCloud مربوط به `personalagent.wealthos.ir` را باز کند تا قواعد مؤثر بررسی شوند. کلید یا رمز نباید در چت فرستاده شود. حساب SSH پروژه، دسترسی مدیریت این CDN/cPanel یا sudo ندارد. این گزارش هنوز به پشتیبانی ارسال نشده است.

## شواهد بدون اطلاعات محرمانه

| بررسی ۱۲ سپتامبر | نتیجه |
|---|---|
| Staging `/api/health` از سرور | کد `be77c3a0d41895fadbf94938b01fa62a1312c5d6`، database connected |
| ۶۵ آزمون HTTPS حساب ساختگی | موفق |
| Origin HTTP داخلی، `/sw.js` و `/pwa-recovery.js` | HTTP 200؛ `Cache-Control: no-cache, no-store, must-revalidate` |
| همان دو URL در HTTPS عمومی Staging | HTTP 200؛ `Server: MizbanCloud`؛ `Cache-Control: max-age=14400`؛ HIT/MISS |
| SHA فایل worker در Origin و CDN | هر دو `e00e53b1890e57bfee548a40f17eb65f61b929db51e7b7dd11148a4a09c47c0c` |
| SHA بازیابی در Origin و CDN | هر دو `242a502d08ed93fd8599968d982f1fb699f98ad4330400c3dab6d350d0f94b82` |
| صفحه ریشه از CDN روی سرور | BYPASS؛ پس کش HTML در لبه از این نمونه ثابت نیست |
| مرورگر این میزبان | رابط قدیمی با chunk `3tgg3x87j1gfr.js`؛ درخواست مستقل health با `ERR_CONNECTION_CLOSED` |
| curl ویندوز به HTTPS Staging | خطای 35 در دریافت handshake؛ متغیرهای proxy این فرایند تنظیم نبودند |
| اتصال HTTPS مستقیم به Origin با حفظ SNI و اعتبارسنجی | گواهی self-signed؛ بدون `-k` متوقف شد؛ TLS دور زده نشد |

## تغییر مجاز پیشنهادی، فقط بعد از دسترسی پنل

1. ابتدا تنظیمات مؤثر CDN/Origin/TLS را از پنل ثبت و پشتیبان بگیرید؛ کد و اطلاعات کاربر تغییر نکند.
2. فقط برای **Staging پورت ۸۴۴۳**، فایل‌های `/sw.js` و `/pwa-recovery.js` از کش اجباری خارج و هدر Origin رعایت شود؛ API و احراز هویت نباید کش شوند. cache مربوط به فایل‌های نام‌هش‌دار JS/CSS بی‌دلیل غیرفعال نشود.
3. اگر قواعد پنل پورت را تفکیک نمی‌کنند، تنظیمی که به Production پورت ۴۴۳ هم اثر می‌گذارد اجرا نشود. برای Staging مستقل/قاعده محدود و DNS لازم ابتدا تصمیم مالک گرفته شود؛ تغییر دامنه یا مهاجرت داده خودکار مجاز نیست.
4. خطای TLS مسیر مرورگر تا لبه و لبه تا Origin با ابزار رسمی میزبان جدا بررسی شود؛ غیرفعال‌کردن اعتبارسنجی SSL، نصب گواهی نامعتبر در دستگاه یا تغییر حدسی پروکسی ممنوع است.
5. کش/کوکی/نشست کاربر یا همه کش CDN پاک نشود. بعد از اصلاح قاعده، ابتدا هدر و SHA دو فایل و سپس بارگیری worker تازه و چهار باکس/شعر بعدی در همان مرورگر بررسی شود؛ دریافت فایل روی سرور به‌تنهایی کافی نیست.
6. روش بازگشت: فقط قاعده محدود Staging به تنظیم پشتیبان برگردد؛ هیچ Snapshot قدیمی روی دیتای تازه نوشته نشود. برای تغییر مشترک Production تأیید نهایی جدا لازم است.

تا موفقیت کنترل تحویل تازه و پذیرش گوشی، پروژه «کاملاً نهایی» نیست. دستیار محلی و APK ۴۰ قابل آزمایش‌اند؛ ChatGPT واقعی و تماس/پیامک اختیاری به رضایت و دسترسی جدا وابسته‌اند.
