## اقدام مدیر سرور، ریسک و بازگشت — فعلاً اجرا نشده

1. از پیکربندی دقیق hostname و سیاست CDN، current هر سرویس و SQLite snapshot بگیرید؛ ساب‌دامین‌های دیگر را وارد rule نکنید.
2. روی همین hostname، پاسخ‌های حساب/API/HTML و worker را از کش مشترک خارج و فایل‌های hashدار عمومی را جدا سیاست‌گذاری کنید. تغییر کش443 نیز اثر Production دارد و نیازمند تأیید است. پاک‌کردن storage/cookie گوشی لازم نیست. تخلیه هدفمند cache CDN فقط پس از تصویب دامنه اقدام انجام شود.
3. اتصال HTTPS عادی از Windows و شبکه گوشی، worker bytes و آدرس backend را جدا مقایسه کنید. تغییر پورت Origin کل hostname را به‌عنوان اصلاح آزمایشی اجرا نکنید.
4. فقط پس از تأیید، نسخه آزموده روی443 منتقل شود؛ دیتابیس واقعی با دیتابیس آزمایشی تعویض نشود. ریسک‌ها: نشست ورود وابسته به origin، نمایش نسخه قدیمی، تغییر زمان‌بندی و ناسازگاری داده. بازگشت با release و rule قبلی است، نه بازنویسی دیتابیس جدید با snapshot قدیمی. هنگام بازگشت scheduler مربوط موقتاً متوقف و سپس با نسخه سازگار بررسی شود.
