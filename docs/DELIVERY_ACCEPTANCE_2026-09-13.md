## اقدام محدود مدیر سرور/دامنه — آماده، ارسال و اجرا نشده

1. ابتدا فقط Virtual Host دقیق `personalagent.wealthos.ir:443` و لاگ همان vhost/CDN با request IDهای بالا بررسی شود. upstream، Host و SNI مشخص شوند. Staging روی loopback 3010 و Production روی 3011 دو محیط/داده جدا هستند. پورت Staging **8443** است، نه 8483. فایل تولیدشده cPanel/LiteSpeed حدسی ویرایش نشود؛ مکانیزم رسمی همان پنل استفاده شود.
2. راه پیشنهادی با حفظ Production، hostname مجزای Staging روی HTTPS عمومی 443 و vhost اختصاصی → `127.0.0.1:3010` است؛ نام/مالکیت/گواهی باید ابتدا تصویب و بررسی شود، هنوز ساخته نشده است. listener عمومی 3010/3011 باز نشود. تغییر پورت Origin رکورد اصلی به 8443 می‌تواند درخواست‌های 443 را نیز به Staging ببرد؛ این انتقال اصلی بدون تأیید ممنوع است.
3. قبل از اجرا: Export همان DNS/CDN/vhost، نسخه/هدف current، env خصوصی و Snapshot سازگار DB، همراه آزمون Restore جدا. گواهی معتبر، Host/SNI و origin/login/cookie hostname منتخب بررسی شوند؛ Secret وارد گزارش نشود.
4. Page Rule فقط برای hostname تصویب‌شده و با matcher واقعاً تأییدشده باشد؛ عدم اثر روی سایر پروژه‌ها ثابت شود. HTML حساب، API/auth، RSC، worker و recovery کش نشوند/Origin no-store رعایت شود؛ فایل‌های هش‌دار می‌توانند کش شوند. اگر فقط zone-wide ممکن است، برای scope دقیق توقف شود. نبود شرط پورت یعنی Rule روی hostname فعلی ممکن است 443 را هم عوض کند؛ نیازمند تأیید است. پاکسازی کلی کش مجاز نیست.
5. پس از تغییر مصوب: HTTPS معتبر و health با Commit درست، Login/Task/Calendar/Notification/تأیید Escalation با حساب ساختگی، از سرور/ویندوز/گوشی؛ هدر و محتوای worker/JS و خود رابط نیز بررسی شوند. Push/Alarm واقعی آزمون گوشی جدا دارند؛ تماس/SMS خاموش بمانند.
6. Rollback: فقط رکورد/Rule/vhost تغییرکرده از Export برگردد؛ syntax-check و reload محدود؛ داده تازه و سایر سرویس‌ها حفظ شوند. بازگشت برنامه به Release قبلی با DB فعلیِ سازگار باشد، نه نوشتن Snapshot قدیمی روی داده تازه. در ناسازگاری نامعلوم، scheduler همان محیط تا بررسی متوقف بماند.

تغییر مقصد در MainActivity فعلی می‌تواند Web Storage/Cookie را پاک کند؛ قبل از تغییر hostname/پورت APK، انتقال داده در نسخه جدا آزموده شود. Package تازه داده قدیمی را خودکار ندارد. ارتقای درجا همان Package، همان گواهی امضا و versionCode بالاتر می‌خواهد؛ حذف برنامه راه‌حل نیست. آماده‌سازی شبکه مجوز تغییر مقصد APK/انتشار عمومی نیست.
