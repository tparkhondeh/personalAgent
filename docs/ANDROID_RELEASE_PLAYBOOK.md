### درس تازه: پنجره سیستم روی WebView

کنترل متن/DOM/رنگ WebView می‌تواند پشت پنجره ANR سیستم هم موفق شود. قبل از تحویل نهایی، تصویر و درخت UI سطح Android نیز باید نبود پنجره Crash/ANR روی برنامه را نشان دهند. ANR Launcher را با Crash همراه یکی نکنید، اما تصویر پوشیده را قبول نکنید. تصاویر/لاگ اولیه حفظ شوند؛ غیرفعال‌کردن Launcher، پنهان‌کردن لاگ یا ادعای رفع اشکال سیستم مجاز نیست. افزودن gate سطح سیستم و آزمون دوباره همان فایل با تصویر بدون پوشش، کار باقی‌مانده کنترل کیفیت است.

تکمیل زیرساخت آزمون کارت کوتاه: `android-system-ui-check.mjs` کنار هر عکس، درخت UI و وضعیت پنجره را نگه می‌دارد و با پنجره Crash/ANR یا نبود hierarchy معتبر شکست می‌خورد. فقط در آماده‌سازی پیش از نصب، پنجره دقیق Pixel Launcher می‌تواند یک بار با دکمه Wait استاندارد و ثبت تصویر اولیه منتظر بازیابی بماند؛ هیچ خطای همراه بسته/پنهان نمی‌شود. کنترل کیبورد با لمس واقعی فیلد، مشاهده وضعیت IME و بررسی جای دکمه و ورودی اجرا می‌شود؛ کوچک‌کردن viewport مرورگر جای این کنترل را نمی‌گیرد.

پس از تکرار Launcher ANR در دو بوت تازه Android 14 و خروج ۱۳۷ ابزار UI در Android 16، RAM شبیه‌ساز ۴۰۹۶ MB تعیین شد. آماده‌سازی پیش از نصب، فقط برای ANR تأییدشده Launcher، حداکثر یک reboot کامل شبیه‌ساز با حفظ لاگ و تصویر هر دو بوت و تکرار warm-up دارد. اگر همراه نصب است، خطا متعلق به برنامه است، dump نامعتبر است یا بوت دوم سالم نشد، این مسیر مجاز نیست و انتشار شکست می‌خورد. این تغییر محیط CI است، نه تغییر APK و نه اثبات سلامت خودکار سیستم‌عامل.

برای اعمال ناهمگام بومی از sleep ثابت به‌عنوان اثبات اتمام استفاده نکنید: آزمون باید پایان تکمیل/حذف همان ID و لغو اعلان را مشاهده کند؛ سپس baseline عدم اثر پیش از تأیید بگیرد. مقایسه صرف تعداد، کاهشِ ناشی از حذف قبلی را هم ممکن است «ایجاد بدون تأیید» گزارش کند. مقایسه مجموعه IDها و ثبت قبل/بعد الزامی است؛ هیچ اختلافی بدون بررسی علت نادیده گرفته نشود. پس از آزمون کیبورد، لغو پیشنهاد و بازگشت/paint صفحه مقصد را نیز بررسی کنید.

گاهی UI Automator بعد از پیام نوشتن dump با خروج ۱۳۷ متوقف می‌شود. این را با Crash همراه یکی نکنید: صرفاً خواندن صفحه حداکثر سه بار، با فایل XML یکتای هر تلاش و حفظ گزارش خطا، قابل تکرار است. XML قدیمی هرگز خوانده نشود؛ اگر همان تلاش ANR/Crash را نشان داد، آن را پنهان یا Retry نکنید. خروج غیر۱۳۷، XML ناقصِ اجرای موفق و شکست مکرر هنوز مانع انتشارند. عکسِ موفق فقط پس از capture معتبر گرفته و بصری بازبینی شود. برنامه/داده/مجوزها در این Retry تغییر نمی‌کنند.

در اجرای 34026468015، خود ابزار `com.android.commands.uiautomator.Launcher` با UID پوسته 2000 هنگام `Shutting down VM`، خطای `Bad file descriptor` روی ترد UiAutomation ثبت کرد. grep سراسری FATAL آن را با خطای همراه یکی می‌گرفت. اکنون `android-logcat-check.mjs` فقط همین الگوی کامل را با تطبیق PID تمام خطوط، و فقط پس از تأیید تازه UI بدون پوشش، جداگانه به‌عنوان خرابی ابزار مشاهده ثبت می‌کند؛ لاگ کامل حفظ می‌شود. Process برنامه، PID متفاوت، الگوی ناقص، Crash ناشناخته، renderer، JavaScript و SSL ناامن همچنان Fail هستند. آزمون مستقل ضدپنهان‌شدن خطا برای این طبقه‌بندی وجود دارد.

## Staging، Backup و Rollback

- Staging فعلی روی `https://personalagent.wealthos.ir:8443` از Production جداست.
- پیش از هر تغییر سرور، از دیتابیس، تنظیمات، Release فعال و وضعیت Processها Backup گرفته می‌شود.
- تغییر Production فقط با تأیید نهایی مالک انجام می‌شود.
- اگر GitHub Runner به پورت Staging دسترسی نداشت، تست رابط محلی و Recovery در Runner ادامه پیدا می‌کند و Smoke Test سرور جداگانه انجام می‌شود؛ بررسی‌ها حذف نمی‌شوند.

## خطاهای کشف‌شده در آزمون همسانی نسخه ۱۵ (۲۰۲۶-۰۹-۰۶ UTC)

- آزمون واقعی سه یادآوری روی هر سه Android شکست خورد: `Native notification bridge missing`. بازشدن رابط به‌تنهایی اثبات کارکرد اعلان نیست؛ نسخه ۱۵ منتشر نشد.
- Capacitor 8.5 صفحه `errorPath` را بدون تزریق پل افزونه‌ها تحویل می‌دهد؛ همچنین اسکریپت شروع سند در حالت متصل فقط برای مبدأ سرور فعال است. `MainActivity` پل استاندارد خود Capacitor را فقط در سند اصلیِ بازیابیِ داخل APK و فقط برای `LocalNotifications` تزریق می‌کند. مبدأها، اعتبارسنجی SSL و مجوزهای سیستم‌عامل تغییر نمی‌کنند.
- فونت باید از فایل داخل APK در مبدأ خصوصی `localhost` خوانده شود؛ مسیر دقیق فونت توسط برنامه سرو می‌شود. آزمون واقعی بارگیری Vazirmatn نیز الزامی است.
- آزمون باید سه اعلان بومی آینده را از فرم واقعی ایجاد کند، در `getPending` ببیند و پس از تکمیل کار لغوشدن آن‌ها را اثبات کند. این کنترل را برای سبزشدن CI حذف نکنید.
- کلید عمومی Web Push اکنون از API احرازهویت‌شده و در زمان اجرای سرور دریافت می‌شود؛ اتصال اعلان نباید به وجود تنظیمات Staging هنگام Build در GitHub وابسته باشد. کلید خصوصی فقط در سرور می‌ماند.
- آزمون نسخه ۱۶ نشان داد `String.replace` در Java تمام `<head>`ها، حتی نمونه داخل رشته JSON رابط جاسازی‌شده، را تغییر می‌دهد و SyntaxError ایجاد می‌کند. درج اسکریپت اکنون با برش در نخستین head واقعی انجام می‌شود؛ تست واحد، دست‌نخورده‌ماندن رشته HTML داخلی و `$` و backslash را کنترل می‌کند. نسخه ۱۶ منتشر نشد.
- نسخه ۱۷ دیگر SyntaxError نداشت، اما تست بارگیری فونت، NetworkError پیدا کرد. برخلاف نام متد، `Bridge.getLocalUrl()` در حالت متصل به مبدأ سرور اشاره می‌کند، نه `localhost`. مبدأ منابع داخل APK اکنون از `getScheme()` و `getHost()` ساخته می‌شود. این تفاوت باید در هر تغییر Capacitor بررسی شود؛ فونت خارج از APK یا نادیده‌گرفتن آزمون راه‌حل نیست. نسخه ۱۷ منتشر نشد.

## امنیت انتشار

- در تغییر صوت/شعر ۲۰۲۶-۰۹-۰۹، وزن مدل دستگاه حداکثر ۴۵ ثانیه قابل استفاده مجدد است، اما recognizer و صوت هر ضبط مستقل‌اند. مسیر سرور tia فقط در حالت متصل، با رضایت تازه و سلامت واقعی سرویس نمایش داده می‌شود؛ هرگز آن را قابلیت آفلاین معرفی نکنید. آزمون تمام ۳۶۰ شعر، متن دقیق، RTL، اندازه خوانا و نبود بریدگی را روی همان WebView فایل تحویلی بررسی کند. شکست طبیعی شعر بلند در عرض کم مجاز است؛ کوچک‌کردن افراطی یا پنهان‌کردن واژه‌ها نه.
- هش کل فایل APK در همه مراحل باید دقیقاً یکسان باشد. هش tar/gzip مدل در بسته‌بندی جداگانه ویندوز و لینوکس ممکن است به‌علت metadata متفاوت شود؛ در این حالت با `verify-released-speech-model.py` تمام فایل‌های بازشده مدل را با ZIP اصلیِ دارای هش ثابت مقایسه کنید. کنترل سخت‌گیرانه بایت‌به‌بایت داخل همان Build را حذف نکنید.

- در آزمون نسخه ۱۸، Android 13 و 16 کامل موفق شدند؛ Android 14 پس از موفقیت فونت و سه اعلان، به‌علت مرگ `com.google.android.gms.persistent` بسته شد. Logcat صریحاً `depends on provider ... FontsProvider in dying proc` را ثبت کرد. این رخداد شبیه‌ساز را با خطای JavaScript برنامه اشتباه نگیرید؛ لاگ را نگه دارید و همان APK را دوباره آزمایش کنید. حذف آزمون آفلاین یا اعلان برای سبزشدن نتیجه مجاز نیست. تا موفقیت هر سه Android، نسخه قابل تحویل نیست.

- APK فعلی آزمایشی و Debug-signed است.
- Keystore، رمز امضا، `.env`، کلید API و اطلاعات شخصی هرگز وارد Git یا Artifact عمومی نمی‌شوند.
- پیامک و تماس تا انتخاب سرویس‌دهنده، شماره تأییدشده و تأیید هزینه در حالت Mock می‌مانند.
- محدودیت‌های Android، SSL، احراز هویت یا محدودیت کشوری دور زده نمی‌شوند.
