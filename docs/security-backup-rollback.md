# امنیت، Backup و Rollback

## کنترل‌های فعال

- نشست و Cookie امن در Production با Better Auth
- محدودسازی همه Queryهای کاربر با `userId`
- اعتبارسنجی ورودی API با Zod
- ثبت عملیات مهم و هشدارها در Audit Log
- جلوگیری از اجرای مستقیم پیشنهاد Agent بدون تأیید کاربر
- حفاظت Endpointهای زمان‌بندی با `CRON_SECRET`
- هدرهای امنیتی مرورگر، جلوگیری از iframe و عدم افشای نام فناوری
- نگهداری Secret، دیتابیس، Keystore و تنظیمات Android خارج از Git
- غیرفعال‌بودن Backup خودکار داده اپ Android برای جلوگیری از انتقال ناخواسته نشست

## Backup محلی

```powershell
pnpm db:backup
```

این دستور با `VACUUM INTO` یک Snapshot سازگار SQLite می‌سازد و همان لحظه `integrity_check` را اجرا می‌کند. خروجی در `backups/local/` قرار می‌گیرد و وارد Git نمی‌شود. فایل Snapshot رمزگذاری‌شده نیست؛ بنابراین فقط باید در فضای امن نگهداری شود.

## بازیابی امن

1. برنامه متوقف شود تا اتصال باز به دیتابیس نماند.
2. از دیتابیس فعلی یک Backup جدا گرفته شود.
3. Snapshot انتخابی ابتدا با `PRAGMA integrity_check` بررسی شود.
4. ابتدا Snapshot در مسیر جدا بازیابی و داده‌ها مقایسه شوند؛ نسخه فعال بازنویسی نشود. جایگزینی دیتابیس فعال فقط پس از مشخص‌شدن داده‌های جدیدی که از دست می‌روند و تأیید صریح مالک مجاز است.
5. Migration، `/api/health`، ورود و ایجاد یک کار آزمایشی بررسی شوند.

بازیابی عمداً خودکار نشده است تا یک دستور اشتباه داده فعلی را بازنویسی نکند.

## Rollback برنامه

در سرور، نسخه‌ها باید در پوشه‌های تاریخ‌دار نگهداری شوند و لینک `current` فقط با Health Check جابه‌جا شود. Rollback با برگرداندن لینک و Process Manager به نسخه قبل انجام می‌شود و دیتابیس فعلی حفظ می‌شود. اگر Migration ناسازگار است، بازگشت متوقف و اصلاح رو‌به‌جلو بررسی شود؛ Snapshot قدیمی نباید خودکار روی داده تازه نوشته شود. زمان‌بند هنگام بازگشت به کدی که سیاست تأیید هشدارها را نمی‌شناسد متوقف می‌ماند تا سازگاری بررسی شود.

هیچ Rollback یا تغییر Production بدون تأیید صریح مالک اجرا نمی‌شود.

## تمرین بازیابی بدون دست‌زدن به برنامه فعال

`node scripts/verify-backup-restore.mjs backups/local/<verified-snapshot>.db`

ابزار فقط Snapshot دارای گزارش سلامت را می‌پذیرد؛ یک مسیر جدید خصوصی می‌سازد، هش فایل، سلامت و کلیدهای خارجی را بررسی و Migration را تنها روی کپی اجرا می‌کند. شمارش و اثرانگشت تمام ردیف‌های قبلی مقایسه می‌شوند، بدون چاپ محتوا. هیچ وب‌سرور، زمان‌بند یا سرویس بیرونی راه نمی‌افتد؛ کپی و گزارش برای بررسی حفظ می‌شوند. فایل پشتیبان رمزگذاری‌شده نیست و نباید در Git یا Release قرار بگیرد.
