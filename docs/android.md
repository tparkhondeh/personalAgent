# اپلیکیشن Android همراه

اپ اندروید با Capacitor 8 ساخته شده و کد اصلی وب را دوباره‌نویسی نمی‌کند. پوشه `android/` پروژه بومی و `mobile-shell/` پوسته امن آفلاین است.

## وضعیت فعلی

- شناسه برنامه: `ir.wealthos.personalagent`
- نام برنامه: «همراه»
- حداقل Android: API 24
- Target: API 36
- RTL، حالت روشن/تاریک، آیکون، Splash و فونت محلی آماده است.
- اعلان محلی و Alarm دقیق با مجوز روشن کاربر پیاده‌سازی شده است.
- پیامک و تماس فقط Mock هستند و هیچ داده یا هزینه‌ای ایجاد نمی‌کنند.
- APK آزمایشی ساخته، امضای آن بررسی و محتوای آن تحلیل شده است.
- Android 16 بدون اتصال گوشی در GitHub Actions بوت شده و نصب، اجرای برنامه و اتصال آن به API و دیتابیس آزمایش شده است.
- نسخه موقت قابل‌نصب مستقیم روی گوشی، بدون کابل و بدون تغییر Production، در GitHub Actions آماده شده است.
- Backup ابری و انتقال خودکار داده برنامه بین دستگاه‌ها صریحاً غیرفعال است.

## ساخت نسخه آزمایشی

نسخه Emulator به برنامه لوکال روی پورت ۳۰۰۱ وصل می‌شود:

```powershell
pnpm android:assets
pnpm android:build:debug
```

خروجی در مسیر زیر ساخته می‌شود:

`android/app/build/outputs/apk/debug/app-debug.apk`

آخرین خروجی بررسی‌شده:

- حجم: ۴٫۱۷ مگابایت
- شناسه: `ir.wealthos.personalagent`
- حداقل Android: ۷ (API 24)
- هدف: Android 16 (API 36)
- SHA-256: `b7c9de0a8f6fc2bf8826e0aff0cf5231216bfbbf087ed2304b1c46a12c7143bc`
- Android Lint: بدون خطا و هشدار
- تست واحد Android: موفق

JDK 21، Android SDK و Gradle به‌صورت قابل‌حذف در پوشه محلی کاربر نصب شده‌اند. دستور ساخت آن‌ها را خودکار پیدا می‌کند. فایل `local.properties`، Keystore، APK و ابزارهای حجیم وارد Git نمی‌شوند.

## آزمایش ابری بدون گوشی

Workflow فایل `.github/workflows/android.yml` در هر تغییر فنی روی شاخه اصلی، محیط تمیز Linux و شبیه‌ساز Android 16 را آماده می‌کند. این فرایند وابستگی‌ها را از Lockfile نصب می‌کند، دیتابیس آزمایشی می‌سازد، وب و APK را Build می‌کند، Android Lint و تست واحد را اجرا می‌کند و سپس ۶ تست Instrumented، نصب APK و Cold Launch برنامه را روی Emulator بررسی می‌کند. تست‌های رفتاری جدید، نمایش و حذف اعلان دارای صدا، رسیدن Alarm دقیق و اجرا نشدن Alarm لغوشده را نیز اثبات می‌کنند.

[اجرای موفق شماره ۵ در GitHub Actions](https://github.com/tparkhondeh/personalAgent/actions/runs/33488117509) بدون گوشی و بدون تغییر Production کامل شد. دو خروجی `hamrah-debug-apk-5` و `hamrah-android-evidence-5` تا ۱۴ روز در همان صفحه قابل دریافت‌اند. SHA-256 فایل APK ابری:

`6becc46ca95c3dcee007f07047f546cc9b9f7c4e5c435cddfecb7fac1d49c0f6`

## نصب آزمایشی بدون کابل

Workflow دستی `.github/workflows/phone-preview.yml` همه اجزای لازم را در یک Runner موقت GitHub Actions می‌سازد: دیتابیس جدا، Secretهای تصادفی، برنامه وب، تونل HTTPS آزمایشی و APK متصل به همان آدرس. سپس سلامت API و دیتابیس، هدرهای امنیتی، دانلود کامل APK و تطابق SHA-256 را بررسی می‌کند. هیچ فایل، پردازش یا تنظیمی در Production تغییر نمی‌کند.

[اجرای پیش‌نمایش شماره ۱](https://github.com/tparkhondeh/personalAgent/actions/runs/33493716896) با موفقیت به مرحله میزبانی موقت رسید. APK آن ۴٬۳۷۰٬۵۲۵ بایت است و SHA-256 زیر را دارد:

`ecbb0d2847d3ae81a4d0b3a46e05be16de0eeac6d5705952100e9ee0298f347f`

لینک نصب در Summary همان اجرا نمایش داده می‌شود و حدود دو ساعت فعال می‌ماند. داده‌های این محیط پایدار نیستند، LLM در حالت محلی امن کار می‌کند و این نسخه فقط برای آزمایش است. برای ساخت لینک تازه کافی است Workflow دوباره اجرا شود. فایل APK و گزارش‌های کنترل کیفیت نیز به‌صورت Artifact تا ۱۴ روز در GitHub نگهداری می‌شوند.

هر اجرای پیش‌نمایش نام «همراه آزمایشی» و شناسه بسته منحصربه‌فرد خودش را دارد. بنابراین اگر نسخه آزمایشی قدیمی با امضای متفاوت یا در فضای مخفی گوشی باقی مانده باشد، نسخه تازه بدون تداخل در کنار آن نصب می‌شود. نسخه‌های آزمایشی قدیمی را می‌توان بعداً بدون اثر بر Production حذف کرد.

برای شبکه‌هایی که آدرس موقت Cloudflare را مسدود می‌کنند، Workflow مستقل `Stable offline phone preview` یک APK بدون `server.url` می‌سازد. این نسخه مدیریت محلی کارها و جلسات، اولویت، ذخیره روی گوشی و Alarm آزمایشی را داخل خود اپ اجرا می‌کند و از GitHub Pre-release با لینک پایدار دریافت می‌شود. این APK به Production، تونل، کلید API یا سرویس پولی وابسته نیست.

رابط همین پیش‌نمایش در مرورگر واقعی روی دسکتاپ و نمای موبایل ۳۹۰×۸۴۴ بررسی شد؛ RTL و چیدمان Responsive درست بود و Console خطا یا هشدار نداشت.

## نصب آزمایشی روی گوشی با USB

این مرحله فعلاً طبق تصمیم مالک پروژه معوق است، اما فرایند آن آماده و خودکار شده است. وقتی زمان آزمایش رسید، برنامه وب باید روی پورت ۳۰۰۱ در حال اجرا باشد و فقط یک گوشی Android مجاز از راه USB متصل باشد. سپس این دستور کافی است:

```powershell
pnpm android:install:device
```

اسکریپت ابتدا سلامت برنامه را بررسی می‌کند، اتصال محلی امن `adb reverse` را می‌سازد، APK مخصوص همان اتصال را Build می‌کند، نسخه قبلی آزمایشی را بدون حذف داده‌ها به‌روزرسانی می‌کند و برنامه را باز می‌کند. اگر گوشی مجاز نباشد، بیش از یک دستگاه وصل باشد یا Build شکست بخورد، نصب متوقف می‌شود. این فرایند به دامنه، Wi-Fi عمومی، کلید API یا Production وابسته نیست.

## وضعیت آزمایش روی دستگاه

محدودیت Virtualization رایانه محلی با انتقال تست به GitHub Actions برطرف شد. شبیه‌ساز ابری Android 16 بوت شد، هر ۶ تست بدون شکست پایان یافت، اعلان و Alarm واقعاً آزمایش شدند، APK نصب شد و `MainActivity` با وضعیت `ok` باز شد. تست گوشی طبق درخواست مالک فعلاً معوق است و فقط برای تأیید نهایی رفتار پس‌زمینه در شرایط واقعی باتری و محدودیت‌های متفاوت سازندگان گوشی لازم خواهد بود.

## نسخه انتشار

`server.url` فقط در Buildهای آزمایشی Emulator یا پیش‌نمایش موقت استفاده می‌شود. این APKها نسخه انتشار عمومی محسوب نمی‌شوند. نسخه انتشار باید پس از تأیید Production با آدرس HTTPS نهایی، امضای خصوصی و تنظیم امن احراز هویت ساخته شود. هیچ آدرس HTTP عمومی در Release پذیرفته نمی‌شود.

## محدودیت آگاهانه هشدار تمام‌صفحه

هشدار تمام‌صفحه برای برنامه‌های عادی بهره‌وری در نسخه‌های جدید Android محدود است. همراه از کانال اعلان با بیشترین اولویت، صدا، لرزش و Alarm دقیقِ دارای رضایت استفاده می‌کند و محدودیت سیستم‌عامل را دور نمی‌زند.
