# درخواست بررسی مسیر اتصال tia — ۱۱ اکتبر ۲۰۲۶

این گزارش فقط تشخیص خواندنی است؛ تنظیمات سرور، دامنه، TLS، حساب، داده و هزینه تغییر نکرده‌اند.

## متن قابل ارسال برای مدیر سرور/شبکه

از محیط Windows توسعه، اتصال به `personalagent.wealthos.ir` کامل نمی‌شود. لطفاً مسیر همین مبدأ را بررسی کنید، نه اینکه صرفاً بازبودن پورت را تأیید کنید:

1. ساعت **۱۴:۰۴:۵۰ تهران، ۱۱ اکتبر ۲۰۲۶** (10:34:50 UTC)، اتصال TCP به IP `185.226.140.40` روی هر دو پورت **443 و 8443** برقرار شد، اما TLS در۱۰ثانیه کامل نشد. HTTP پاسخی نداده؛ خطای404 یا گواهی نامعتبر مشاهده نشده است. DNS دو IPv4 یعنی `185.226.140.40` و `185.226.142.42` برگرداند؛ این نمونهٔ تازه فقط IP اول را انتخاب کرد.
2. روی SSH موجود `62.204.61.18:2490`، TCP و بنر `OpenSSH_8.0` دریافت می‌شود. در10:32:13 UTC تبادل `KEXINIT` انجام شد و الگوریتم `curve25519-sha256` انتخاب شد، اما کلاینت در انتظار `SSH2_MSG_KEX_ECDH_REPLY` ماند و مهلت۱۸ثانیه تمام شد؛ هنوز پذیرش/رد کلید ورود رخ نداده است. بررسی رمز یا ساخت کلید تازه قدم اول نیست.
3. لطفاً در زمان‌های بالا، لاگ فایروال/ACL، محدودیت یا مسدودسازی IP مبدأ، TLS/SNI همین زیردامنه و لاگ SSH را بررسی و در صورت نیاز مسیر رفت‌وبرگشت/MTU را مقایسه کنید. MTU یا CDN فقط فرضیه‌اند، نه علت اثبات‌شده. مبدأ محلی کلاینت `172.18.0.1` خصوصی است؛ IP خروجی عمومی باید از لاگ شبکه/درگاه NAT مشخص شود.
4. درخواست: HTTPS معتبر با نام دقیق همین زیردامنه روی443/8443 و SSH موجود بدون تغییر مقصد/شناسه/کلید دوباره از همین کلاینت قابل استفاده شوند. TLS را دور نزنید و تنظیمات مشترک `wealthos.ir` یا سایر پروژه‌ها را تغییر ندهید. اگر تغییر لازم شد، هدف دقیق، اثر و روش بازگشت را پیش از اجرا مشخص کنید.

صفحه Staging در آزمون۱۰اکتبر از GitHub با TLS عادی باز شده بود؛ بنابراین این شواهد اثبات قطعی عمومی سرور نیستند. ممکن است مسیر همین کلاینت یا سیاست وابسته به مبدأ دخیل باشد. سیاست کش بعد از برقراری TLS/HTTP بررسی می‌شود؛ پاک‌کردن کش/کوکی یا داده کاربر این آزمایش را اصلاح نمی‌کند.

## شواهد و ادامه

- بررسی عمومی `/api/health` روی443/8443 در10:27:20 UTC هر دو `UND_ERR_CONNECT_TIMEOUT`؛ آزمایش جدا TCP/TLS بالا محل توقف را دقیق‌تر کرد.
- رسید محلی بدون کلید یا محتوای کاربر: `project-backups/tia-android16-20261011/network-current.json`؛ کلید خصوصی SSH خوانده/نمایش داده نشده، فقط کلاینت استاندارد از هویت موجود استفاده کرد.
- پس از رفع دسترسی: عامل ابتدا وضعیت و نسخه واقعی، فضای نوشتن و دفتر بودجه را فقط می‌خواند، سپس پیش از هر نصب مجاز Staging پشتیبان/بازیابی جدا را بررسی می‌کند. هیچ بودجهٔ جدید یا بازنشانی هزینه برای دورزدن این مانع ایجاد نمی‌شود.
