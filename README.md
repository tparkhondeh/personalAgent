# tia — Personal Agent

tia یک دستیار شخصی فارسی و مینیمال برای کارها، جلسات، تقویم و یادآوری‌هاست. برنامه‌ریز محلی فعال است؛ تبدیل صدای فارسی نیز روی خود دستگاه انجام می‌شود. LLM خارجی هنوز به کلید معتبر و رضایت هزینه وابسته است. هیچ کار یا هشداری پیش از تأیید نهایی پیشنهاد اجرا نمی‌شود.

[سابقه اصلاح نام، لوگو و صوت نسخه ۳۷](docs/TIA_RELEASE_2026-09-07.md) محفوظ است؛ صوت محلی به سرویس بیرونی ارسال نمی‌شود و اجرا همچنان نیازمند تأیید است.

پذیرش میکروفون و جمله‌های واقعی روی گوشی مالک باقی است. ورودی آزمون صوت، نمونه عمومی با میکروفون مصنوعی بود؛ runner به Staging نرسید و HTTPS میزبان توسعه نیز مشکل اتصال داشت، پس Android متصل روی شبکه مالک ادعا نمی‌شود. تشخیص محلی ممکن است اشتباه کند؛ متن و زمان‌ها را قبل از ثبت بررسی کنید. LLM خارجی و تماس/پیامک واقعی فعال نشده‌اند؛ تنظیم Push سرور موجود ولی تحویل واقعی به گوشی تأیید نشده است. Production تغییر نکرده؛ APK قبلی را برای حفظ اطلاعات محلی حذف نکنید. لینک‌های تاریخی پایین، نسخه پیشنهادی نصب نیستند.

## امکانات MVP

- رابط RTL، Responsive، پاستلی و Dark Mode با فونت محلی وزیرمتن
- شعر روز مولانا با ۳۶۰ رباعی کامل و معتبر، ثابت برای هر روز و قابل استفاده بدون اینترنت
- کارهای شخصی و شرکتی با اولویت فوری، مهم و عادی
- جلسات و نمای تقویم هفتگی
- تنظیمات کاربر شامل ساعت کاری، روزهای کاری و زمان‌های یادآوری؛ گزینه سبک برنامه‌ریزی حذف شده است
- ثبت‌نام و ورود امن با Better Auth
- SQLite/LibSQL و Prisma با جداسازی داده هر کاربر
- Audit Log برای عملیات داده
- گفتگوی ساختاریافته با حالت محلی یا LLM و تأیید پیش از اجرا
- دو یا سه یادآوری پیش‌فرض هم‌زمان برای هر کار و جلسه، مرکز اعلان، اعلان محلی و زیرساخت Web Push
- PWA قابل نصب روی موبایل و دسکتاپ با پوسته آفلاین پایه
- پروژه بومی Android با Capacitor، آیکون و Splash اختصاصی
- ساخت APK، آزمایش خودکار Android 13/14/16 و پیش‌نمایش HTTPS پایدار قابل‌نصب بدون کابل در GitHub Actions
- هشدار چندمرحله‌ای کار فوری: اعلان، Alarm اندروید، اولویت بالا، Mock امن پیامک و تماس واقعیِ محافظت‌شده و اختیاری
- Backup سازگار SQLite، کنترل Rollback و هدرهای امنیتی
- تست Unit، Type Check، Lint، Build و CI

## اجرای محلی

پیش‌نیاز: Node.js 24 و pnpm 11.

```powershell
pnpm install
Copy-Item .env.example .env
pnpm db:generate
pnpm db:init
pnpm dev
```

سپس `http://localhost:3000` را باز کنید. مقادیر Secret و کلید API فقط در `.env` قرار می‌گیرند؛ این فایل وارد Git نمی‌شود.

## کنترل کیفیت

```bash
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm audit --prod --audit-level high
```

## اپلیکیشن Android

نسخه آزمایشی فعلی «همراه پایدار 28» با شناسه `ir.wealthos.personalagent.stable28` است. همین فایل روی Android 13، 14 و 16 آزمون شده؛ محدودیت اتصال آنلاین runner و شواهد تصویری در گزارش بالا ثبت است و پذیرش گوشی مالک هنوز معوق است. نسخه قدیمی را برای حفظ داده محلی حذف نکنید؛ اطلاعات محلی بین شناسه‌های مستقل خودکار منتقل نمی‌شوند. برای جلوگیری از تکرار مشکل صفحه سفید، علت‌ها، راه‌حل‌ها و کنترل‌های اجباری در [راهنمای دائمی ساخت و تحویل Android](docs/ANDROID_RELEASE_PLAYBOOK.md) ثبت شده‌اند.

نسخه آزمایشی Android ساخته شده و با `pnpm android:build:debug` دوباره تولید می‌شود. خروجی محلی در `android/app/build/outputs/apk/debug/app-debug.apk` قرار می‌گیرد. پس از اتصال و تأیید USB debugging روی یک گوشی، دستور `pnpm android:install:device` ساخت، اتصال امن محلی، نصب و بازکردن برنامه را خودکار انجام می‌دهد. نسخه عمومیِ امضاشده تا تأیید آدرس امن Production ساخته نمی‌شود.

### یکسان‌بودن ظاهر اپ با نسخه لوکال

نسخه‌های نصب‌شده خودکار با Commit شدن کد تازه نمی‌شوند: رابط متصل از Release فعال Staging خوانده می‌شود و رابط آفلاین از فایل‌های داخل همان APK. پس از تغییرات وب، هر دو باید جداگانه بررسی و به‌روزرسانی شوند. Workflow پایدار اکنون APK و بسته Linux همان Commit را با هم می‌سازد. شعر و تاریخ و سه یادآوری در رابط محلی نیز هماهنگ شده‌اند؛ داده‌های حالت محلی با حساب سرور همگام نمی‌شوند.

در APK پایدار فعلی **دو حالت** وجود دارد:

- **متصل به سرور (`server.url`)**: همان نسخه‌ای است که باید UI آن دقیقاً شبیه مرورگر لوکال شود؛ مناسب برای تأیید نهایی.
- **آفلاین (`mobile-shell`)**: رابط سبک‌تر داخل همان APK برای سناریوی بدون اینترنت؛ فونت، شعر، تاریخ و سه یادآوری هماهنگ‌اند، ولی چیدمان و داده مستقل هستند.

برای خروجی متصل، به‌صورت پیش‌فرض در محیط توسعه با `pnpm android:build:debug` ساخته می‌شود و باید روی `localhost:3001` (یا استیجینگ معادل) تست شود.

مسیر معتبر فعلی تحویل، Workflow `Verified stable Android preview` است: [اجرای موفق نسخه ۲۲](https://github.com/tparkhondeh/personalAgent/actions/runs/34013442504). APK فقط پس از موفقیت هر سه Android منتشر می‌شود؛ همان فایل تحویلی نصب و آزموده شده است. روش‌های موقت زیر فقط سابقه‌اند و برای تحویل تازه نباید استفاده شوند.

## متغیرهای محیطی

نمونه کامل در `.env.example` است. Production حداقل به `DATABASE_URL`، تنظیمات Better Auth، کلیدهای VAPID و `CRON_SECRET` نیاز دارد. کلید LLM اختیاری است و نبود آن برنامه را به حالت محلی امن می‌برد.

در محیط توسعه، خالی‌بودن کلید LLM مانع کار برنامه نیست؛ دستیار به‌صورت خودکار از حالت محلی امن استفاده می‌کند. همچنین بدون کلید VAPID می‌توان اعلان محلی همین دستگاه را آزمایش کرد.

### فعال‌سازی سرویس‌های بیرونی

- دستیار بدون کلید در حالت محلی کار می‌کند. برای اتصال واقعی OpenAI باید `OPENAI_API_KEY` در فایل محیطی امن سرور قرار گیرد و سپس یک درخواست آزمایشی کنترل‌شده اجرا شود.
- تماس واقعی برای شماره‌های ایران از مسیر کاوه‌نگار آماده شده است. فعال‌شدن آن هم‌زمان به `OUTBOUND_CALLS_MODE=live`، کلید `KAVENEGAR_API_KEY`، قرارگرفتن شماره تأییدشده در `OUTBOUND_CALL_VERIFIED_NUMBERS` و روشن‌بودن گزینه تماس در حساب کاربر نیاز دارد.
- تا وقتی هر چهار شرط تماس برقرار نباشد، تماس فقط شبیه‌سازی و در Audit Log ثبت می‌شود. متن تماس عمومی است و عنوان یا جزئیات خصوصی کار به سرویس تماس فرستاده نمی‌شود.
